# Цифровая станция — цифровой двойник железнодорожной станции (демо-MVP)

Учебно-демонстрационная **система поддержки решений** диспетчера. Она объединяет в одном состоянии:
- расписание и операции станции;
- занятость путей, ресурсы и ограничения;
- телеметрию IoT-устройств.

На этом состоянии система проверяет заявки на приём, обнаруживает конфликты, перепланирует операции (OR-Tools CP-SAT) и объясняет результаты.

> ⚠️ **Важно.** Все данные синтетические. Станция «Алматы (демо)», её схема, ограничения и показатели **демонстрационные** и не соответствуют реальной станции. Система не управляет стрелками, сигналами и движением поездов и **не является** сертифицированной системой обеспечения безопасности движения.

## Что умеет

| Возможность | Где посмотреть |
|---|---|
| Проверка приёма состава: план месяца (цель или жёсткая квота), перерабатывающая и пропускная способность, длина состава и путей, маршрут по топологии, ресурсы, соседняя станция, данные датчиков | «Заявки» → «Проверить приём» |
| Рассчитанное ближайшее окно и проверенные альтернативы: перенос, другая станция, изменение очереди, разделение партии | Результат проверки |
| Транзакционное резервирование: защита от двойного бронирования ограничением-исключением PostgreSQL, идемпотентность команд | «Подтвердить заявку» |
| 2D-схема и 3D-двойник (Three.js / R3F) на одном состоянии от backend | «Обзор станции» |
| Диаграмма Ганта по путям, локомотивам и бригадам; сравнение текущего и предложенного плана | «План и Гант» |
| Перепланирование CP-SAT с лимитом 3,5 с, честный статус решения, независимая проверка плана | «Рекомендации», «План и Гант» |
| Индекс эффективности 0–100 с настраиваемыми весами, порогами и качеством оценки | «Загрузка и индекс», «Настройки» |
| IoT: симулятор устройств → Mosquitto → приём с валидацией → качество данных («Неизвестно» блокирует подтверждение) | «Датчики и связь» |
| Перемотка последних 5–15 минут, режимы «Сейчас», «История», «Прогноз» | Переключатель в шапке |
| Помощник: объясняет серверные расчёты по шаблонам, без внешней LLM | «Помощник» |
| Мини-отчёт PDF и CSV (кириллица), журнал событий и аудит | «Загрузка и индекс», «Журнал» |

## Быстрый запуск

Нужен Docker Desktop (Compose v2) и около 2 ГБ свободной памяти.

```bash
cp .env.example .env          # необязательно: без .env используются демо-значения
docker compose up -d --build
```

Откройте **http://localhost:8080**. Описание API (Swagger) — http://localhost:8000/docs.

При первом запуске backend применяет миграции Alembic и заполняет БД демо-данными: конфигурация `large`, сценарий «Обычная работа», seed 42. Начальный план оптимизируется CP-SAT — первый старт занимает около 40 секунд. Симуляция стартует с ускорением ×5.

Первая загрузка каждого рабочего сценария в «Настройках» занимает ~25 с (оптимизация начального плана), повторные — меньше секунды (кэш).

| Сервис | Порт | Назначение |
|---|---|---|
| frontend (nginx) | 8080 | интерфейс; проксирует `/api` и `/ws` |
| backend (FastAPI) | 8000 | API, WebSocket, движок симуляции, приём телеметрии, планировщик |
| db (PostgreSQL 16) | 5432 | состояние, история, аудит |
| mqtt (Mosquitto 2) | 1883 | приём телеметрии (анонимный доступ запрещён, ACL на топики) |
| simulator | — | программные IoT-устройства (`source_mode=simulator`) |

### Демонстрационные доступы (пароль `demo123`)

| Логин | Роль | Что может |
|---|---|---|
| `train` | Поездной диспетчер | создать, проверить и перенести заявку |
| `station` | Станционный диспетчер | перепланирование, применение плана, ручной перенос операций, инциденты |
| `duty` | Дежурный по станции | подтверждение, отказ, отмена заявки; инциденты; ручное уточнение датчика |
| `admin` | Администратор | симуляция и сценарии, конфигурация индекса, политики и пороги |
| `viewer` | Наблюдатель | только просмотр и выгрузка отчёта |

Права проверяются на сервере для каждой изменяющей операции. Ролевая модель — допущение MVP: полномочия должен проверить профильный специалист.

### Демонстрационные сценарии

Сценарий выбирается в «Настройки → Симуляция» (роль `admin`). Каждый воспроизводим по сценарию и seed.

| Сценарий | Что показывает |
|---|---|
| Заявка: план выполнен, место есть | Предупреждение о превышении плана; при «жёсткой квоте» — отказ |
| Заявка: пути заняты на время прибытия | Отказ с объяснением, ближайшее окно и альтернативы — всё рассчитано |
| Заявка: сейчас заполнено, к прибытию освободится | Приём разрешён: проверен весь интервал |
| Пик прибытий, закрытие пути, задержка грузовой операции, неисправный вагон, ограничение соседа, восстановление | Конфликты, перепланирование, рекомендации |
| Потеря связи с датчиком | Путь получает статус «Неизвестно», подтверждение блокируется, затем перезапуск устройства и восстановление |
| Сквозной сценарий IoT и перепланирования | Полный поток из раздела 27 задания |
| 5 и 10 одновременных нештатных ситуаций | Нагрузочный пересчёт плана |

Пошаговый сценарий показа для жюри — [docs/demo.md](docs/demo.md).

## Проверки

```bash
# backend: 42 теста на реальной PostgreSQL (база station_test, миграции Alembic)
docker compose run --rm --no-deps -e ENGINE_ENABLED=false -v ./backend:/app backend python -m pytest tests -q

# frontend: unit-тесты и сборка
cd frontend && npm ci && npm test && npm run build

# сквозной сценарий показа (docs/demo.md) на запущенном стенде
docker compose run --rm --no-deps -v ./tools:/tools simulator python /tools/demo_e2e.py

# замеры производительности (стек должен быть запущен)
docker compose run --rm --no-deps -v ./tools:/tools simulator python /tools/bench.py
```

Фактические результаты и условия измерения — в [docs/testing.md](docs/testing.md) и [docs/performance.md](docs/performance.md).

## Структура

```
backend/      FastAPI, SQLAlchemy, Alembic, OR-Tools; app/services — бизнес-логика, app/iot — приём телеметрии
  app/configs/  конфигурации станций: large.json (Алматы, демо), small.json (Шамалган, демо)
  tests/        интеграционные тесты на PostgreSQL
frontend/     React + TypeScript + Vite + React Three Fiber
simulator/    симулятор IoT-устройств (MQTT)
mosquitto/    конфигурация брокера, ACL, генерация паролей из переменных окружения
tools/        нагрузочный стенд bench.py
docs/         документация (требования, архитектура, ADR, API, планирование, IoT и др.)
presentation/ презентация (HTML, 12 слайдов)
```

Смена станции: в `.env` задайте `STATION_CONFIG=small` либо выберите станцию в «Настройках». Бизнес-логика не меняется — топология строится из конфигурации.

## Известные ограничения

- Модель технологии упрощена: нормативные длительности, маршрут — кратчайший путь по схеме, состав маневрирует целиком. Перечень упрощений — в [docs/domain.md](docs/domain.md).
- Один процесс backend: движок симуляции работает в памяти процесса. Гарантии от двойного бронирования обеспечивает БД и при нескольких процессах.
- Реальные устройства подключаются через MQTT с `source_mode=real`; на стенде используется только симулятор.
- Внешняя языковая модель отключена (`LLM_PROVIDER` пуст), объяснения строятся по шаблонам.
- Схема станции не в масштабе.
