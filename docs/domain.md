# Предметная область: термины, роли, сущности, допущения

## Термины

| Термин | Значение в модели |
|---|---|
| Основная станция | Подробно моделируемая станция (`stations.kind = main`): «Алматы (демо)» (`large`) или «Шамалган (демо)» (`small`) |
| Соседняя станция | Упрощённое состояние (`kind = neighbor`): время хода, макс. длина поезда, число приёмных путей, занятость путей интервалами, локомотивы |
| Парк | Группа путей одного назначения: приёмо-отправочный, сортировочный, грузовой, ремонтный, главные пути |
| Путь | Ребро топологии с полезной длиной (м), разрешёнными видами поездов и связанной зоной |
| Стрелка (узел) | Узел «лестницы» горловины (`W<k>`, `E<k>`); резервируется на время движения по маршруту |
| Маршрут | Кратчайший путь по графу от входа до пути / между путями; транзит возможен только по главному пути |
| Стоянка | Непрерывный интервал занятия одного пути поездом (от заезда до окончания выезда) |
| Операция | Технологический шаг: прибытие, техосмотр, манёвры, выгрузка/погрузка, расформирование, отцепка вагона, ремонт, стоянка, отправление |
| Резерв | Запись `reservations` на интервал по ключу ресурса: `track:`, `switch:`, `res:` |
| Заявка | Запрос соседней станции на отправление состава на основную станцию |
| Инцидент | Нештатная ситуация, меняющая исходные данные модели |
| Конфликт | Нарушение жёсткого ограничения в прогнозном плане |
| Версия состояния | Счётчик `plan_state_version`; растёт при изменениях, влияющих на проверки и план |
| Модельное время | Время симуляции (`sim_state.model_time`), идёт со скоростью ×N |

## Роли и права

Предварительная ролевая модель MVP. Права проверяются на backend для каждой изменяющей операции (`app/core/permissions.py`, зависимость `require(action)`). Состав полномочий — допущение команды; перед промышленным использованием требует проверки профильным специалистом (технологом станции, службой движения).

| Роль | Назначение |
|---|---|
| Поездной диспетчер (`train_dispatcher`) | Межстанционные перемещения, заявки, перенос отправления |
| Станционный диспетчер (`station_dispatcher`) | Планирование обработки, ресурсы, применение плана, ручной перенос операций |
| Дежурный по станции (`duty_officer`) | Подтверждение/отказ по заявкам, ручное уточнение показаний датчиков |
| Администратор (`admin`) | Симуляция, сценарии, конфигурация индекса, политики, пороги |
| Наблюдатель (`observer`) | Только просмотр и выгрузка отчёта |
| Осмотрщик вагонов (`wagon_inspector`) | Мобильный раздел: осмотр, сообщения о дефектах, назначенные осмотры |
| Осмотрщик-ремонтник (`wagon_inspector_repairer`) | Возможности осмотрщика и выполнение назначенного ремонта; свой ремонт не принимает |
| Оператор ПТО (`pto_operator`) | Приём и маршрутизация сообщений, уточнения; не применяет план и не разрешает движение |
| Слесарь по ремонту подвижного состава (`rolling_stock_fitter`) | Задания своей бригады: начало, пауза, отчёт, фото |
| Старший осмотрщик-ремонтник (`senior_wagon_inspector`) | Распределение заданий в своей зоне, контрольный осмотр, возврат на доработку |

Рабочие роли работают только в мобильном разделе и не получают снимок станции. Права процесса работников — в [mobile.md](mobile.md).

## Упрощения железнодорожной технологии

1. Горловины — «лестницы» стрелок; маршрут — кратчайший путь по графу; одновременно через стрелку проходит одно движение (без учёта враждебности по сигналам и параллельных маршрутов).
2. Схема не в масштабе; полезная длина пути — параметр конфигурации.
3. Состав перемещается целиком; отцепка неисправного вагона — отдельная операция с подачей в депо, ремонт вагона — отдельная операция без поезда.
4. После расформирования вагоны выходят из модели и учитываются как обработанные; сортировка по назначениям не моделируется.
5. Время перехода бригады/локомотива между зонами — фиксированная подготовка перед операцией (`zone_travel_min`).
6. Смены задаются интервалами (`day`, `night`, круглосуточно); перерывы и нормы труда не моделируются.
7. Соседние станции — упрощённая модель: время хода, ограничения, занятость приёмных путей интервалами.
8. Технологический запас пути после освобождения — 5 мин (`track_buffer_min`), запас по длине — 10 м.
9. Месячный план считается по вагонам с завершённым техосмотром.
10. Сигнализация, ограничения скорости, тяговые расчёты и требования безопасности движения не моделируются.

## Допущения по данным

- Длина вагона по роду: полувагон 13,92 м, крытый 17,64, цистерна 12,02, платформа 14,62, хоппер 14,72; локомотив 34 м.
- Количество вагонов не заменяет длину: без длины состава и рода вагонов проверка возвращает «Недостаточно данных».
- Отсутствие нового RFID-события не подтверждает отсутствие вагона; потеря координат локомотива не означает освобождение пути.

## Управление ролями и пользователями

Раздел интерфейса «Пользователи и роли» и API `/api/v1/admin/*`. Все изменения доступны **только системной роли «Администратор»** (право `users.manage`) и проверяются на сервере. Остальным ролям раздел показывает матрицу прав только для чтения.

| Правило | Как обеспечено |
|---|---|
| Другие роли не видят администрирование и Swagger | Пункты меню «Пользователи и роли» и «API (Swagger)» показываются только при наличии прав; маршрут `/admin` перенаправляет на обзор; `/docs`, `/openapi.json`, `/api/v1/permissions` — 403 |
| Добавлять роли и пользователей может только администратор | Все эндпоинты `/admin/*` требуют `users.manage`; остальные роли получают 403 `FORBIDDEN` |
| Пользовательская роль не может получить право управлять ролями | `users.manage` зарезервировано: попытка выдать его возвращает 400 `PERMISSION_RESERVED`; при чтении прав из БД оно отбрасывается |
| Системные роли неизменны | Их права заданы в коде; изменение или удаление — 409 `SYSTEM_ROLE_READONLY` |
| Роль нельзя удалить, пока она назначена | 409 `ROLE_IN_USE` |
| Нельзя потерять управление стендом | Блокировка или смена роли последнего активного администратора — 409 `LAST_ADMIN` |
| Изменения действуют сразу | Права читаются из БД при каждом запросе (кэш 2 с, сбрасывается при изменении); заблокированный пользователь теряет действующий токен |
| Прозрачность | `role.create`, `role.update`, `role.delete`, `user.create`, `user.update`, `user.password` — в аудите |

Пользовательская роль всегда получает базовое право «Просмотр состояния». Остальные права выбираются из матрицы.

На экране входа показываются только демонстрационные учётные записи. Пользователи, созданные администратором, там не перечисляются.
