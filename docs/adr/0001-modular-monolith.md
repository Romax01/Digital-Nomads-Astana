# ADR-0001. Модульный монолит вместо микросервисов

**Статус:** принято.

## Контекст
MVP должен работать по одной команде на ноутбуке участника (≈ 4 ГБ памяти под Docker), показывать сквозной поток «событие → решение → аудит» и проходить интеграционные тесты на реальной БД. Задание прямо просит не добавлять микросервисы без конкретной потребности.

## Варианты
1. Микросервисы: приём IoT, планировщик, API, realtime — отдельные сервисы с брокером между ними.
2. Модульный монолит: один процесс backend с чёткими модулями (`api`, `core`, `domain`, `services`, `iot`, `sim`), БД — единственный источник истины.

## Решение
Вариант 2. Отдельными контейнерами вынесено только то, что имеет иную природу: PostgreSQL, MQTT-брокер, симулятор устройств и статический frontend (nginx).

## Последствия
- Простое развёртывание, малое потребление памяти (стек ≈ 320 МБ), транзакции в одном процессе.
- Гарантии целостности (ограничение-исключение, advisory lock, идемпотентность) обеспечивает БД, поэтому они не зависят от числа процессов API.
- Движок, приём и hub работают в одном процессе (`--workers 1`). Для масштабирования их нужно вынести в отдельный процесс и заменить внутреннюю шину межпроцессной (ADR-0002).
