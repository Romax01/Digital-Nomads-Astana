# Качество данных

Реализация — `backend/app/iot/quality.py`.

## Состояния данных

| Состояние | Когда | Влияние |
|---|---|---|
| actual — актуальные | последнее принятое измерение моложе порога устаревания, качество не `bad`, расхождений нет | используется |
| stale — устаревшие | возраст измерения > `stale_after_s` устройства | путь «Неизвестно», операции на нём блокируются |
| missing — отсутствующие | датчик есть, принятых измерений нет | то же |
| contradictory — противоречивые | показание датчика расходится с учётным положением поезда по журналу операций дольше 6 с | то же; сохраняются оба наблюдения |
| invalid — некорректные | последнее сообщение устройства отклонено (единица, диапазон и т. п.) или quality = bad | то же |
| not_monitored | датчик не установлен | используется учётное состояние |

Состояние **подключения** устройства (heartbeat: online / offline / нет данных) — отдельный признак. Устройство считается offline, если heartbeat не поступает дольше max(15 с, 3 × период).

## Ключевые правила

1. **Устаревшее ≠ свободно.** Без актуальных данных путь никогда не считается свободным, а ресурс — исправным.
2. **Блокировка зависящих операций.** Для пути со статусом stale, missing, contradictory или invalid в книге интервалов создаётся блокировка `data` от текущего момента. Последствия:
   - проверка заявки отклоняет этот путь с причиной `DATA` и сообщением, например: «Данные занятости: путь 3 устарели. Последнее измерение получено 18 секунд назад. Подтверждение приёма на этот путь недоступно»;
   - планировщик не выбирает путь кандидатом;
   - движок не начинает на него заезд;
   - детектор показывает конфликт «Нет достоверных данных» для операций в ближайшие 6 ч.
3. **Восстановление.** Когда приходят свежие данные и расхождение исчезает, путь возвращается в actual. Монитор в hub фиксирует смену категории: пишет доменное событие и увеличивает версию состояния. Блокировка снимается, рекомендации пересчитываются.
4. **Наблюдение, резерв и прогноз разделены.** Телеметрия «свободно» не отменяет будущую бронь автоматически.
5. **Интервалы рассчитываются автоматически** из времени измерения, а не задаются текстом.

## Противоречие источников

Расхождение «датчик: свободен» при поезде на пути по журналу операций (или «занят» при пустом пути) становится противоречием, только если длится дольше `CONTRADICTION_GRACE_S = 6 с`. Более короткое расхождение считается задержкой доставки. Сообщение объясняет обе версии, например: «Противоречие: датчик сообщает „путь 1 свободен“, а по журналу операций там поезд № 2001. Сохранены оба наблюдения…».

## Ручное уточнение

Дежурный по станции (`observation.override`) может временно задать значение занятости пути. Нужны значение, основание (не менее 5 символов) и срок действия 1–120 мин реального времени. На время действия путь считается актуальным с источником «ручное уточнение». Показания датчика продолжают сохраняться. Действие и отмена записываются в аудит и увеличивают версию состояния.

## Особые сообщения

| Случай | Обработка |
|---|---|
| Повтор (тот же event_id) | отбрасывается без повторного действия |
| Не по порядку (seq ≤ последнего в том же boot_id) | сохраняется как `late`, наблюдение не заменяет |
| Опоздавшее по времени (observed_at старше текущего наблюдения) | сохраняется, не заменяет более новое |
| Retained / старше порога | `stale`, не «освежает» данные |
| Перезапуск (новый boot_id, время не раньше последнего наблюдения) | новый сеанс, счётчик с нуля, доменное событие «Устройство перезапущено» |
| Сообщение прежнего сеанса после перезапуска | `late` |
| Пропавший heartbeat | связь offline, на основном экране — предупреждение для значимых устройств |

## Пороги по умолчанию

Рельсовые цепи — 8 с, стрелки — 20 с, RFID — 30 с, ГНСС — 6 с, механизмы — 20 с, диагностика — 30 с. Изменяются администратором по типу источника (`PUT /config/device-thresholds`, с аудитом).
