# Требования и критерии приёмки

Документ фиксирует требования к демонстрационному MVP «Цифровая станция» и честный статус их выполнения на момент сдачи. Статусы: **реализовано**, **частично** (с пояснением), **нет**.

## 1. Назначение

Учебно-демонстрационная система поддержки решений: цифровой двойник одной подробно моделируемой станции (по умолчанию «Алматы (демо)») и двух соседних станций с упрощённым состоянием («Отар (демо)», «Жетыген (демо)»). Система показывает текущее и прогнозное состояние, проверяет возможность приёма составов, обнаруживает конфликты, предлагает проверенные альтернативы и перепланирование, объясняет причины.

Система **не** управляет стрелками, сигналами и движением, не является сертифицированной системой обеспечения безопасности. Все данные синтетические; схема, нормы и показатели станции «Алматы (демо)» не соответствуют реальной станции.

## 2. Границы MVP

| В MVP | Вне MVP |
|---|---|
| Одна подробная станция (конфигурации `large` и `small`), две упрощённые соседние | Реальная сеть дорог, точная топология реальных станций |
| Программный симулятор IoT-устройств через MQTT | Подключение реального оборудования (только адаптерный контракт `source_mode=real`) |
| Детерминированная проверка ограничений + CP-SAT | Обучение собственной нейросети |
| Шаблонные объяснения помощника, адаптер внешней LLM (выключен) | Обязательная зависимость от внешнего LLM API |
| Процедурная 3D-визуализация (длины в масштабе, поперечные размеры увеличены) | Фотореалистичная графика |
| Docker Compose: db, mqtt, backend, simulator, frontend | Микросервисы, Kafka/RabbitMQ, горизонтальное масштабирование |

## 4. Нефункциональные требования

| № | Требование | Статус | Комментарий |
|---|---|---|---|
| N1 | Поток состояния ≥ 1 Гц | реализовано | тик 1 с + внеочередная сборка по событию |
| N2 | Видимое обновление < 500 мс после события в backend | частично | серверная часть (событие → отправка в WebSocket) измерена, клиентская отрисовка измеряется только в видимой вкладке — см. performance.md |
| N3 | Пересчёт плана после сбоя ≤ 5 с | реализовано | лимит решателя 3,5 с, результат — лучший допустимый план с честным статусом |
| N4 | 5 и 10 одновременных инцидентов без зависания | реализовано | тесты `test_replan_5_incidents`, `test_replan_10_incidents` |
| N5 | Интерфейс на русском, цвет дублируется текстом/значком | реализовано | `lib/labels.ts` |
| N6 | Доступность с клавиатуры | частично | пути, составы, операции, вкладки, модальные окна доступны; полноценный аудит доступности не проводился |
| N7 | Секреты в переменных окружения, учётные данные MQTT не попадают на frontend | реализовано | `.env.example`, `mosquitto/entrypoint.sh` |
| N8 | Хранение телеметрии 24–72 ч, отдельная политика аудита | реализовано | `TELEMETRY_RETENTION_HOURS`, аудит 365 дней (параметр) |

## 5. Допущения

- Часовой пояс станции — `Asia/Almaty` (UTC+5); в БД всё хранится в UTC.
- Модельное время симуляции и реальное время разделены: операции живут в модельном времени, связь и устаревание данных датчиков — в реальном.
- Демо-дата 01.10.2026, старт симуляции 12:00 по времени станции.
- Нормативы длительностей операций, длины вагонов, время хода между станциями — демонстрационные значения из конфигурации.
- Ролевая модель — предварительная, требует проверки профильным специалистом.
