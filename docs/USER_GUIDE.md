## 1. Что это за система

«Цифровая станция» — **цифровой двойник железнодорожной станции** и **система поддержки решений** диспетчера. В одном общем состоянии собраны:
- расписание и технологические операции станции (прибытие, осмотр, манёвры, выгрузка, отправление);
- занятость путей, локомотивы, бригады, ограничения;
- данные датчиков (IoT): рельсовые цепи, стрелки, GPS локомотивов и другие;
- сообщения работников о неисправных вагонах и заявки на ремонт.

На этом состоянии система:
- проверяет, можно ли принять состав;
- находит конфликты в плане;
- перепланирует операции (решатель OR-Tools CP-SAT);
- объясняет свои выводы;
- показывает всё в 3D, на диаграмме Ганта и в таблицах.

> **Важно.** Это демонстрационный стенд на синтетических данных. Станции «Алматы (демо)» и «Шамалган (демо)», их схемы, ограничения и показатели условные. Система **не управляет** стрелками, сигналами и движением поездов и **не является** сертифицированной системой обеспечения безопасности движения. Все решения и подтверждения в ней — учебные.

**Из чего состоит система:**
- **Основное приложение (кабинет)** — работает на ПК диспетчера, открывается в браузере.
- **Мобильное приложение работников** `/mobile` — дополнение к основному. Телефоны подключаются к тому же ПК по Wi-Fi.
- **Сервер, база данных, MQTT-брокер и симулятор датчиков** работают в контейнерах Docker на том же ПК.

## 2. Запуск

### 2.1 На любом ПК одним файлом (рекомендуется)
Нужны Windows 10/11 и интернет на время первой установки. Больше ничего ставить вручную не нужно: батник сам проверит Docker Desktop и, если его нет, предложит установить.

1. Скопируйте на компьютер файл **`start-digital-station.bat`** (он лежит в корне проекта и на GitHub).
2. Запустите его двойным щелчком.
3. На вопрос «Открыть доступ из локальной сети?» ответьте:
   - **Д** — если с программой будут работать телефоны или другие ПК в Wi-Fi;
   - **Н** — если она нужна только на этом компьютере.
4. Дождитесь сообщения «Готово». Первый запуск занимает 5–15 минут (скачиваются образы и собирается программа), следующие — секунды. Браузер откроется сам.

Что батник делает сам:
- скачивает программу с GitHub в `%LOCALAPPDATA%\DigitalStation\app`;
- создаёт для этой установки собственные пароли;
- выбирает свободные порты: если 8080 занят, возьмёт 8081 и запомнит;
- ничего не трогает в других программах и контейнерах.

Команды батника (запускать из командной строки):

| Команда | Что делает |
|---|---|
| `start-digital-station.bat` | запуск (повторный — за секунды) |
| `start-digital-station.bat stop` | остановить, данные сохраняются |
| `start-digital-station.bat status` | состояние контейнеров |
| `start-digital-station.bat update` | скачать новую версию, настройки сохраняются |
| `start-digital-station.bat uninstall` | удалить контейнеры и данные (спросит подтверждение) |

После запуска в окне остаётся **меню «Управление станцией»** — нажмите клавишу:

| Клавиша | Действие |
|---|---|
| **1** | открыть основное приложение в браузере |
| **2** | открыть мобильную версию |
| **3** | открыть сетевой адрес (если включён доступ из сети) |
| **S** | состояние контейнеров |
| **X** | остановить сервис и выйти (данные сохраняются) |
| **Q** | закрыть консоль, сервер продолжит работать |

Если что-то пошло не так, окно не закроется и покажет ошибку. Подробный журнал запуска лежит в `%TEMP%\digital-station-launch.log`.

### 2.2 Из папки проекта (для разработчиков)
```bash
docker compose up -d --build      # запуск
docker compose stop               # остановка (данные сохраняются)
```
При первом старте сервер сам применяет миграции базы и создаёт демо-данные. Батник, лежащий в папке проекта, работает именно с этой папкой.

### 2.3 Адреса

| Что | Адрес |
|---|---|
| Основное приложение на этом ПК | `http://localhost:8080` (или порт, который назвал батник) |
| Мобильное приложение | `http://localhost:8080/mobile` |
| С телефона или другого ПК в той же Wi-Fi | `http://<IP-адрес ПК>:8080` и `…/mobile` — батник показывает точный адрес |
| Описание API (Swagger) | только для администратора: пункт меню «API (Swagger)» |

**Безопасность сети.** В сеть открываются только интерфейс (порт 8080) и MQTT (1883). Сервер API и база данных доступны лишь на самом ПК.

## 3. Вход, роли и права

У всех демо-учёток пароль **`demo123`**. На экране входа их можно выбрать щелчком.

### Кабинет (ПК)

| Логин | Роль | Главное в работе |
|---|---|---|
| `train` | Поездной диспетчер | заявки на приём составов между станциями, перенос отправления |
| `station` | Станционный диспетчер | план станции, применение плана и рекомендаций, решения по сообщениям работников |
| `duty` | Дежурный по станции | подтверждение и отказ по заявкам, инциденты, ручное уточнение показаний датчиков |
| `admin` | Администратор | пользователи и роли, симуляция и сценарии, настройки, Swagger |
| `viewer` | Наблюдатель (жюри) | только просмотр и выгрузка отчёта |

### Мобильное приложение (работники ПТО)

| Логин | Роль | Главное в работе |
|---|---|---|
| `inspector` | Осмотрщик вагонов | сообщения о дефектах с фото, назначенные осмотры |
| `repairer` | Осмотрщик-ремонтник | то же и назначенный ремонт |
| `pto` | Оператор ПТО | приём и маршрутизация сообщений, уточнения, отказ, дубликаты |
| `fitter`, `fitter2` | Слесарь (бригады BR-1, BR-2) | задания своей бригады |
| `senior`, `senior2` | Старший осмотрщик-ремонтник | распределение заданий в своей зоне, контрольный осмотр (приёмка) |
| `otr_inspector` | Осмотрщик другой станции | показывает изоляцию: чужие данные не видны |

**Как устроены права:**
- Права проверяет сервер при каждом действии, а не только интерфейс. Если действие недоступно, рядом с кнопкой написано почему.
- Управлять пользователями и ролями и открывать Swagger может **только администратор**.
- Работники видят только свои сообщения, задания и очередь своей зоны. Снимок станции и 3D им не выдаются.

## 4. Интерфейс кабинета

### Шапка (сверху)
Слева направо:
- **Станция** и пометка «ДЕМО».
- **Модельное время** — время в симуляции, а не на часах компьютера.
- **Режим симуляции:** «▶ Симуляция ×N», «⏸ Пауза» или «● Реальное время». Ниже — название сценария.
- **Переключатель «Сейчас / История / Прогноз»:**
  - **Сейчас** — живое состояние;
  - **История** — перемотка последних 5–15 минут: кадры, воспроизведение, скорость. Изменения в этом режиме недоступны;
  - **Прогноз** — как будут заняты пути через 15 минут — 8 часов по плану. Это прогноз, а не показания датчиков.
- **Индекс эффективности** (0–100) с категорией: «Норма», «Внимание», «Критично».
- **Связь** с сервером и время последних данных. «Обновления задерживаются» или красная полоса «Нет соединения» означают, что на экране может быть устаревшее состояние.
- **🔔 Уведомления:** сообщения работников, назначения, приёмка работ.
- **Тема** (светлая или тёмная) и пользователь с кнопкой «сменить пользователя».

### Меню (слева)
- **Работа:** Обзор станции, Заявки, Расписание, План и Гант.
- **Данные:** Загрузка и индекс, Датчики и связь, Сообщения работников, Журнал, Помощник.
- **Система:** Настройки, Пользователи и роли, API (Swagger).

Счётчики рядом с пунктами показывают, что требует внимания: конфликты, новые заявки, проблемы датчиков, новые сообщения работников. Меню сворачивается до значков кнопкой «Свернуть меню» внизу.

Внизу каждого экрана — копирайт «© Digital Nomads 2026».

## 5. Обзор станции: 3D-двойник

Главный экран. В центре — 3D-сцена, справа — панель «Карточка / Конфликты / Рекомендации / Датчики», снизу — временная шкала операций.

### 5.1 Два уровня
- **Сеть** — карта со станциями и перегонами между ними:
  - основная станция — «Подробная модель», соседние — «Упрощённая модель»;
  - на перегонах видны поезда с номером, числом вагонов и направлением;
  - двухпутный перегон показан двумя путями.
- **Станция** — подробная модель основной станции: пути с рельсами и шпалами, стрелочные переводы, платформа, склады, депо, датчики, составы из отдельных вагонов разных родов.

Как переключаться: кнопки «Сеть › Алматы (демо)» в панели над сценой, кнопка «← К сети», или щелчок по станции на карте сети → «Открыть станцию».

### 5.2 Панель над сценой

| Группа | Кнопки |
|---|---|
| **Уровень** | Сеть / название станции / «← К сети» |
| **Камера** | общий вид **сети**; общий вид **станции**; **объект** — перелёт к выбранному; **следовать** за выбранным поездом (включается и выключается той же кнопкой) |
| **Поиск** | станция, перегон, номер поезда или пути → Enter |
| **Показатели** | индекс, конфликты, задержки ≥ 5 минут, свободные пути парка А, датчики (щелчок открывает нужную вкладку) |
| **Вид** | скрыть или показать правую панель и временную шкалу, полноэкранный режим |

### 5.3 Управление камерой
- **Мышь:** левая кнопка — поворот, правая — перемещение по карте, колесо — приближение к точке под курсором.
- **Клавиатура** (курсор над сценой): **W A S D** или стрелки — полёт по карте, **Q / E** — ниже и выше, **Shift** — быстрее.
- Камеру нельзя увести за край карты. Граница карты и граница станции показаны пунктиром.

### 5.4 Как читать сцену
- **Статус пути** — цветная полоса и подпись со значком: ○ Свободен, ■ Занят, ◇ Зарезервирован, ? Неизвестно, ! Противоречие, ✕ Закрыт. Конфликт подсвечивается пульсацией.
- **Подписи поездов:** номер, число вагонов, текущая операция, задержка (+N′), ⚠ — неисправность. «⛔ ждёт решения по сообщению о дефекте» — поезд задержан до решения диспетчера.
- **Цвета подсветки:** голубой — выбранный объект, жёлтый — объекты, затронутые рекомендацией.
- **Возраст данных** — в левом нижнем углу сцены. При потере связи движение останавливается и показывается предупреждение.
- **Щелчок** по пути, поезду, стрелке, зданию, датчику, станции или перегону открывает **карточку** справа. Выбор только показывает объект и ничего не меняет.

### 5.5 Правая панель и временная шкала
- **Карточка** — подробности выбранного объекта и доступные действия. Для поезда это состав, операции, дефекты и работы; для пути — данные датчика, резервы и кнопка «Закрыть путь».
- **Конфликты** — что нарушает план и почему.
- **Рекомендации** — предложения планировщика с эффектом «до → после». Кнопки: «Показать на схеме», «Сравнить планы», «Применить».
- **Датчики** — проблемы данных, влияющие на решения.
- **Временная шкала** — диаграмма Ганта по путям или ресурсам. «Развернуть Гант» показывает её крупнее.

## 6. Главные рабочие сценарии

### 6.1 Принять ли состав: заявки между станциями
Раздел **«Заявки»**.

1. **Создать заявку** (поездной или станционный диспетчер): откуда, сколько вагонов, род груза, желаемое время.
2. **Проверить приём.** Сервер проверяет:
   - месячный план;
   - перерабатывающую и пропускную способность;
   - длину состава и путей;
   - маршрут по топологии;
   - бригады и локомотивы;
   - соседнюю станцию;
   - достоверность данных датчиков.

   Результат: «можно принять» с планом приёма или «нельзя» с причинами по каждому пути. В ответе также ближайшее допустимое окно и **проверенные альтернативы**: перенос, другая станция, изменение очереди, разделение партии.
3. **Подтвердить заявку** может только **дежурный по станции**. Перед подтверждением показано, что именно будет зарезервировано. Двойное бронирование одного пути исключено на уровне базы данных.
4. **Перенести отправление, отменить или отказать** — с указанием основания.

Каждое действие записывается в «Журнал».

### 6.2 Конфликт → перепланирование → рекомендация
1. **Когда возникает конфликт:** после инцидента (например, закрыт путь), из-за задержки или устаревших данных датчика. Он появляется на вкладке «Конфликты», а объект на 3D подсвечивается.
2. **Расчёт рекомендации.** Планировщик CP-SAT пересчитывает план автоматически, примерно за 1–4 секунды. Результат — **рекомендация** с эффектом: конфликты, задержка и индекс до и после.
3. **«Показать на схеме»** подсвечивает затронутые поезда и пути.
4. **«Сравнить планы»** (раздел «План и Гант») показывает текущий и предложенный план рядом и список изменённых операций.
5. **«Применить»** рекомендацию могут станционный диспетчер и дежурный по станции; применить план целиком в «План и Гант» — только станционный диспетчер. Устаревшую рекомендацию применить нельзя: состояние изменилось, нужно нажать «Пересчитать».

### 6.3 Инциденты
Регистрируются в карточке объекта (станционный диспетчер, дежурный):
- **закрытие пути** — с интервалом; после устранения — «Открыть путь»;
- **неисправность стрелки**;
- **отказ ресурса** (локомотив, бригада);
- **неисправный вагон** (в карточке поезда). Создаётся сообщение с ограничением: поезд не уйдёт, пока по сообщению не принято решение и работы не приняты контрольным осмотром (см. 7.3). Закрыть такой инцидент раньше нельзя.

### 6.4 Датчики и качество данных
Раздел **«Датчики и связь»**: каждое устройство, отдельно состояние связи (heartbeat) и качество последнего измерения.
- **Устаревшие данные никогда не считаются «путь свободен».** Такой путь получает статус «Неизвестно», и подтвердить приём на него нельзя.
- **Ручное уточнение показаний** — дежурный по станции, с основанием и сроком действия (кнопка «Уточнить показания» в карточке пути).
- Внизу раздела — журнал отклонённых сообщений датчиков с причинами.

### 6.5 Расписание, план и Гант
- **«Расписание»** — плановые и прогнозные времена прибытия и отправления, задержки, фильтры.
- **«План и Гант»** — полная диаграмма по путям, локомотивам и бригадам; сравнение планов; статус решения, время расчёта, допущения; кнопки «Пересчитать план» и «Применить план».

### 6.6 Загрузка, индекс и отчёт
Раздел **«Загрузка и индекс»**:
- индекс эффективности — из каких составляющих он сложился и что его снижает;
- месячный план и виды ограничений;
- загрузка путей по часам и занятость ресурсов;
- **выгрузка мини-отчёта в PDF и CSV.**

### 6.7 История и прогноз
- **История** (переключатель в шапке): окно 5, 10 или 15 минут, ползунок, «Воспроизвести», скорость ×1–×10, «Вернуться к текущему». Кадры восстанавливаются из сохранённых изменений.
- **Прогноз**: ползунок времени вперёд. Пути и составы показаны по прогнозному плану, с подписью «прогноз».

### 6.8 Помощник
Раздел **«Помощник»** объясняет расчёты сервера простым языком. Примеры вопросов:
- «Почему нельзя принять этот состав?»
- «Когда появится ближайшее окно?»
- «Что произойдёт, если путь 3 закроется на час?»
- «Какие операции создают перегрузку?»
- «Как уменьшить задержку?»

Помощник не принимает решений: он показывает факты из расчёта, а если данных не хватает, говорит, чего именно.

### 6.9 Журнал
Раздел **«Журнал»**: события станции и аудит. Для каждого действия видно, кто, когда и что сделал, состояние «было / стало» и основание.

## 7. Мобильное приложение работников ПТО

Открывается на телефоне по адресу `http://<IP-ПК>:8080/mobile` в обычном браузере. Его можно добавить на главный экран: «Установить приложение» или «На экран „Домой“». Внизу — разделы «Главная», «Сообщить», «Задания», «Уведомления», «Профиль»; их состав зависит от роли.

### 7.1 Сообщить о дефекте (осмотрщик)
1. **«Сообщить о дефекте».**
2. **Вагон** — одним из способов:
   - найти по номеру;
   - «Выбрать из состава»: поезд → вагон;
   - QR-код (в браузерах, которые поддерживают сканирование);
   - если вагон не найден — указать номер вручную. Сообщение уйдёт «без привязки», вагон привяжет оператор.
3. **Категория:** колёсная пара, буксовый узел, тормозное оборудование, автосцепка, кузов или рама, другое. Затем узел, описание и **срочность**:
   - обычная;
   - срочная;
   - **предположительно критическая** — поезд с этим вагоном сразу задерживается до проверки.
4. **Фото** с камеры или из галереи (до 6, сжимаются на телефоне).
5. Поставьте отметку «Сведения проверены» и нажмите **«Отправить»**.

**Без связи** сообщение сохраняется на телефоне («Ожидает отправки») и уходит **один раз** при восстановлении связи. Черновик сохраняется автоматически. Если сессия истекла, приложение попросит войти снова — данные не теряются.

### 7.2 Приём сообщения (оператор ПТО, диспетчер)
«Задания → Очередь сообщений» или в кабинете «Сообщения работников»:
- **Подтвердить получение** — автор увидит, что сообщение принято. Это отдельно от отметки «доставлено на сервер».
- **Запросить уточнение** — автор отвечает, сообщение возвращается на рассмотрение.
- **Привязать к вагону**, **Отклонить** (с основанием), **Объединить как дубликат**.

### 7.3 Решение, работы, приёмка
1. **Решение** — только станционный диспетчер, кнопка «Принять решение». Варианты:
   - дополнительный осмотр;
   - ремонт без отцепки;
   - отцепка и ремонт (нужен ремонтный путь);
   - **замена вагона в составе** (исправный порожний вагон того же рода);
   - передача на другую ремонтную площадку.

   Сразу можно назначить исполнителя.
2. **Исполнитель** (слесарь, осмотрщик-ремонтник) в «Задания → Мои задания»: «Начать работы» → «Приостановить» или «Возобновить» → отчёт и фото → **«Передать на контрольный осмотр»**. Если нужна отцепка или замена, работы начинаются только после выполнения операции по составу — карточка показывает, когда место будет готово.
3. **Старший осмотрщик** в «Задания → На осмотр»: **«Принять результат»** или **«Вернуть на доработку»** с замечаниями. **Собственную работу принять нельзя.**
4. **Когда вагон снова «исправен»:** после приёмки, и только если у него не осталось других неустранённых дефектов. При замене снятый вагон остаётся неисправным, пока по нему не создана, не выполнена и не принята отдельная заявка на ремонт («Дополнительная заявка»).

В кабинете диспетчера всё это видно в «Сообщениях работников», в колокольчике уведомлений и в карточке поезда на 3D. Кнопка «Показать на цифровом двойнике» переводит к вагону на сцене.

## 8. Администрирование и настройки

### 8.1 Пользователи и роли (только администратор)
- **Роли.** Системные роли неизменны. Можно создать пользовательскую роль с выбранными правами. Права «Управление пользователями и ролями» и «Описание API» выдать нельзя.
- **Пользователи.** Создание, смена роли, блокировка, смена пароля. Последнего администратора заблокировать нельзя.
- **Привязка «станция / ПТО / бригада»** — определяет, какие сообщения и задания видит работник.

### 8.2 Настройки
**Симуляция и сценарии** (администратор):
- **Скорость** ×1, ×5, ×10, ×30, ×60, пауза и запуск.
- **Сценарий**, seed и станция («Алматы» — большая, «Шамалган» — малая, без депо и сортировки):
  - «Обычная работа», «Пик прибытий», «Закрытие пути», «Задержка грузовой операции»;
  - «Неисправный вагон», «Ограничение соседней станции», «Восстановление после инцидента»;
  - «Потеря связи с датчиком», «Сквозной сценарий IoT и перепланирования»;
  - нагрузочные «5 / 10 одновременных нештатных ситуаций»;
  - демонстрация заявок: «план выполнен», «пути заняты», «к прибытию освободится».
- **Флажок «Реальное время»** — модель идёт по часам сервера (×1). Пауза или смена скорости выключают этот режим.
- **«Сбросить и загрузить сценарий»** возвращает мир к начальному состоянию сценария (занимает до минуты).

Расписание пополняется автоматически при любой скорости, поэтому станция не пустеет.

**Индекс эффективности:** веса составляющих, нормализация, пороги категорий. Каждое изменение сохраняется новой версией и записывается в аудит.

**Политики и пороги данных** — например, через сколько секунд показания датчика считаются устаревшими.

## 9. Частые вопросы и проблемы

| Вопрос | Ответ |
|---|---|
| **На станции стоит поезд и не уезжает** | Посмотрите подпись и карточку поезда. «⛔ ждёт решения по сообщению о дефекте» — в составе вагон с предположительно критическим дефектом; нужно решение в «Сообщениях работников». Другие причины видны в карточке («Ожидает: …») и на вкладке «Конфликты». |
| **Поездов почти нет или они мелькают** | На высокой скорости (×30, ×60) поезда проходят станцию за секунды. Поставьте ×5–×10 или «Реальное время». Расписание пополняется само; для свежего начала — «Сбросить и загрузить сценарий». |
| **Путь «Неизвестно», подтвердить приём нельзя** | Нет свежих данных датчика. Проверьте «Датчики и связь». Дежурный может ввести ручное уточнение с основанием. |
| **Кнопка неактивна** | Под кнопкой написано почему: не та роль, режим «История», устаревшая проверка или рекомендация. |
| **Не открывается с телефона** | Телефон и ПК должны быть в одной Wi-Fi. Нужен доступ из сети (батник: ответ «Д» или запуск `… network`). Адрес — `http://<IP-ПК>:8080/mobile`. Проверьте, не блокирует ли брандмауэр Windows Docker Desktop. |
| **«Нет соединения с сервером»** | Сервер или Docker остановлены. Запустите батник ещё раз или выполните `docker compose up -d`. Экран показывает последнее полученное состояние. |
| **3D не отображается** | Браузер без WebGL. Откроется сообщение со ссылками на табличные разделы — все функции там доступны. |
| **Батник показывает ошибку** | Прочитайте текст в окне. Журнал — `%TEMP%\digital-station-launch.log`. Частые причины: Docker Desktop не запущен, мало места на диске. |
| **Забыли пароль администратора** | Демо-пароль — `demo123`. Если его сменили, его может сменить другой администратор в «Пользователях и ролях». |

## 10. Бэкап и восстановление

Копия состоит из:
- истории кода (git bundle) и архива кода;
- дампа PostgreSQL (`pg_dump -Fc`);
- архива фотографий работников.

Готовые копии с инструкцией `КАК-ВОССТАНОВИТЬ.txt` лежат в `C:\Users\<пользователь>\бекапы\`.

Восстановление базы (стек запущен):
```bash
docker compose cp database.dump db:/tmp/database.dump
docker compose stop backend simulator
docker compose exec db sh -c "dropdb -U station station && createdb -U station station && pg_restore -U station -d station /tmp/database.dump"
docker compose start backend simulator
```

## 11. Ограничения демонстрационной версии
- **Данные синтетические**, сеть станций условная. Соседние станции — только упрощённая модель.
- **Перегоны.** На перегонах нет датчиков: положение поезда там рассчитывается по расписанию.
- **Мобильное приложение:**
  - push-уведомлений нет, уведомления видны внутри приложения;
  - QR-сканер работает не во всех браузерах (поиск по номеру работает везде);
  - перегрузка груза при замене гружёного вагона не реализована: сервер откажет с объяснением.
- **Роли и права** — продуктовая модель MVP, требует согласования с внутренними процессами организации.

Подробная техническая документация — в папке `docs/`:
- `twin-3d.md` — 3D;
- `mobile.md` — процесс работников;
- `api.md` — API;
- `realtime.md` — обновления в реальном времени;
- `planning.md` — планировщик;
- `iot.md` — датчики;
- `demo.md` — сценарий демонстрации.
