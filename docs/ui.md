# Интерфейс

Frontend — React 18 + TypeScript + Vite; 3D — React Three Fiber. Все подписи, ошибки и уведомления на русском. Единое состояние приходит по WebSocket, а 3D-двойник, Гант и панели строятся из него. Подробно о 3D — [twin-3d.md](twin-3d.md).

## Основной экран («Обзор станции»)

| Область | Содержание |
|---|---|
| Шапка | станция + отметка «ДЕМО», модельное время и часовой пояс, режим симуляции (▶ ×N / ⏸) и сценарий, переключатель «Сейчас / История / Прогноз», индекс с категорией и временем расчёта, состояние подключения и время последних данных, тема, пользователь и роль |
| Верхняя панель двойника | уровень `Сеть › Станция` и «← Вернуться к сети», режимы камеры («Сеть», «Общий вид станции», «Выбранный объект», «Следовать за поездом»), поиск, краткие KPI, «▤ Панель», «▭ Шкала», «⤢ Во весь экран» |
| Центр | только 3D-сцена (переключателя 2D/3D нет): уровень, режим, пометка «Демо-данные», возраст данных сервера, легенда статусов |
| Правая панель (сворачивается) | вкладки «Карточка», «Конфликты», «Рекомендации», «Датчики»; карточки поезда, пути, стрелки, зоны, датчика, станции, перегона |
| Низ (сворачивается) | временная шкала (Гант) по путям или ресурсам, «Развернуть Гант» — полная диаграмма на месте |

## Принципы

- **Цвет не единственный носитель смысла:** у каждого статуса есть значок и текст (○ Свободен, ■ Занят, ? Неизвестно, ! Противоречие, ✕ Закрыт, ⚠ Конфликт). «Неизвестно» показывается пунктиром, закрытие — штриховкой.
- **Недоступная кнопка объясняет причину** текстом под ней (компонент `ActionButton`), например: «Подтверждение — роль „Дежурный по станции“» или «Проверка устарела: состояние станции изменилось».
- **Последствия до подтверждения:** что будет зарезервировано, какие предупреждения нужно принять, что произойдёт с резервами при отмене или переносе.
- **Состояния:** загрузка (спиннер с текстом), пусто (объяснение и подсказка), ошибка (сообщение, подсказка, код, «Повторить»), потеря связи (красная полоса «Показано последнее полученное состояние…» и «Переподключиться»), задержка обновлений («Обновления задерживаются (N с)»).
- **Актуальность данных:** время расчёта у проверок, рекомендаций и индекса; возраст измерения у путей и устройств.
- **Постепенное раскрытие:** правило и источник ограничения, допущения, история версий — в `details`.
- Без WebGL показывается сообщение, ссылки на табличные разделы и таблица состояния путей; все команды доступны в разделах.

## Реальное время

При первом запуске (`SIM_REAL_TIME=true` в `docker-compose.yml`) и при сбросе с флажком «Реальное время» в «Настройках»:
- модель стартует от текущего момента;
- модельное время идёт ×1 по часам сервера, без накопления ошибки тиков;
- в шапке — «● Реальное время».

Сценарий сохраняет свои интервалы относительно старта: 12:00 сценария равно моменту запуска. Поэтому часы в описаниях сценариев («с 12:20») означают «через 20 минут после старта».

Расписание пополняется автоматически: когда до конца остаётся меньше 4 ч, добавляются поезда на следующие 4 ч. Новые поезда размещаются по текущим резервам без двойных бронирований, номера поездов и вагонов не повторяются, смены бригад продлеваются по суткам.

Пауза или смена скорости выключают режим. Вернуться в него можно сбросом с флажком.

## Режимы

| Режим | Поведение |
|---|---|
| Сейчас | живое состояние |
| История | перемотка последних 5/10/15 мин: выбор момента, воспроизведение, пауза, скорость ×1–×10, «Вернуться к текущему»; команды недоступны |
| Прогноз | занятость путей на выбранный момент (+15 мин … +8 ч) по прогнозному плану, с явной подписью «не наблюдение датчиков» |

## Доступность с клавиатуры

Подписи объектов 3D-сцены (щелчок), поиск, полосы Ганта, строки таблиц и конфликты доступны клавишей Tab и выбираются Enter. У них есть `aria-label` с текстом статуса. Модальные окна получают фокус, закрываются Esc и возвращают фокус. Есть ссылка «Перейти к содержимому». Вкладки размечены ролями `tablist`/`tab`. Видимый фокус — жёлтая обводка. Учитывается `prefers-reduced-motion`.

## 3D-двойник

Сцена использует идентификаторы и координаты схемы из `/topology` и модель сети из `/network`. Позиции составов рассчитывает backend. Клиент лишь интерполирует голову состава вдоль той же ломаной, по которой нарисованы рельсы, не дальше конечной точки операции (`headNow`, `fracNow`) и не при потере связи. Каждый вагон ставится по двум тележкам на ломаной. Кузова, тележки, колёсные пары и шпалы рисуются через `InstancedMesh`, подписи — DOM-слоем с раскладкой без наложений. 3D-модуль загружается лениво. Подробности — [twin-3d.md](twin-3d.md).

## Адаптивность

Сетки перестраиваются при ширине < 1100 и < 760 px: боковая панель уходит под схему, навигация становится горизонтальной.
