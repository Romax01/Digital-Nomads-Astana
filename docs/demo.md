# Демонстрация для жюри (≈10 минут)

Подготовка: `docker compose up -d --build` и браузер на http://localhost:8080. Держите открытыми две вкладки:
- **А** — вход как `admin`, для управления сценариями;
- **Б** — основная, в ней переключаемся между `duty` / `station` / `train` через «сменить пользователя».

Перед показом в «Настройках» выберите сценарий и нажмите «Сбросить и загрузить сценарий». Сброс воспроизводит одно и то же состояние при одинаковом seed (42).

Все уведомления, окна и объяснения в сценарии **рассчитываются** — заранее записанных текстов нет.

## 1. Обзор станции (1 мин)
- Шапка: станция «Алматы (демо)» с отметкой ДЕМО, модельное время UTC+5, режим симуляции, «Сейчас / История / Прогноз», индекс эффективности, состояние связи и время данных.
- В центре — 2D-схема: статус пути показан цветом **и** значком. Переключение на 3D-двойник: то же состояние, вагоны через instancing, «Общий вид».
- Клик по пути или составу открывает карточку. Внизу — Гант по путям и ресурсам; клик по операции выделяет её на схеме.
- Клавиатура: Tab по путям, Enter — выбор.

## 2. Главный сценарий: 40 вагонов от станции Отар (3 мин)
Заявка `Z-0001`: 40 полувагонов, отправление 13:00, ход 90 мин, прибытие 14:30.

1. **«Заявка: план выполнен, место есть»** → «Заявки» → «Проверить приём».
   Результат: «Приём возможен с предупреждениями» — план месяца превышен, политика «целевой показатель».
   Затем в «Настройках» включите «жёсткую квоту» и проверьте снова — теперь отказ.
2. **«Заявка: пути заняты на время прибытия»** → «Проверить приём».
   Результат: «Приём 40 ваг. в 14:30 недоступен: нет подходящего свободного пути на время приёма и обработки. Ближайшее допустимое окно — HH:MM».
   Покажите:
   - причины по каждому пути (путь 6 короче состава, пути 1–5 заняты, с указанием поездов и интервалов);
   - проверенную альтернативу «Перенести отправление» с задержкой и изменением загрузки.

   Кнопка «Подтвердить заявку» недоступна, и рядом написано почему. Прямой запрос к API тоже вернёт `409 REQUEST_NOT_AVAILABLE`.
3. **«Заявка: сейчас заполнено, к прибытию освободится»** → «Проверить приём».
   Результат: «Приём возможен: путь 2…» и пояснение «Сейчас путь занят (…), освободится к 13:57 — до начала приёма».
   Войдите как `duty` → «Подтвердить заявку». Окно предпросмотра покажет, что будет зарезервировано. После подтверждения появятся резервы, поезд на Ганте и запись в «Журнал → Аудит».

## 3. IoT и качество данных (2 мин)
Сценарий **«Потеря связи с датчиком»**, затем «Запустить».
- Через ~3 мин модельного времени рельсовая цепь пути 3 замолкает.
- Через 8 с путь получает статус «? Неизвестно», появляется предупреждение: «Данные занятости: путь 3 устарели. Последнее измерение получено N секунд назад. Подтверждение приёма на этот путь недоступно».
- Клик по предупреждению открывает путь и зависимые операции. Проверка заявки исключает путь 3 с причиной «нет данных».
- Через 60 с устройство перезапускается: новый `boot_id`, журнал «Устройство перезапущено». Данные снова актуальны, блокировка снимается.
- «Датчики и связь»: связь и качество данных показаны раздельно, есть отклонённые сообщения с причинами и история устройства.

## 4. Инцидент → перепланирование → решение → аудит → перемотка (3 мин)
Сценарий **«Сквозной сценарий IoT и перепланирования»**:
1. Как `duty` подтвердите заявку `Z-0001`, затем «Запустить» (вкладка А).
2. На 30-й минуте модельного времени закрывается путь, запланированный для заявки. В панели «Конфликты» — «Операция на закрытом пути».
3. Планировщик сам выдаёт рекомендацию «Применить план № N». В ней: причина, затронутые поезда, эффект (конфликты, задержка, индекс до и после), статус решения CP-SAT и время расчёта.
4. «План и Гант» → «Показать предложенный план» → таблица изменённых операций.
5. Как `station` → «Применить план». Сервер перепроверит состояние: если оно изменилось, вернёт «План устарел — пересчитайте».
6. Все представления обновятся, действие появится в аудите.
7. Шапка → «История» → окно 10 мин → «Воспроизвести»: видно, как закрылся путь и как пришло решение. «Вернуться к текущему».
8. «Загрузка и индекс» → «Отчёт PDF / CSV».

## 5. Нагрузка (по желанию)
Сценарий «10 одновременных нештатных ситуаций» → «Рекомендации» → «Пересчитать». Покажите время расчёта и честный статус: «Найден допустимый план (оптимальность не доказана за отведённое время)».

## Если что-то пошло не так
- «Нет соединения»: интерфейс показывает последнее состояние с предупреждением и сам переподключается. Можно нажать «Переподключиться».
- Сбросьте сценарий кнопкой в «Настройках» — состояние восстановится детерминированно.
