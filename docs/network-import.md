# Формат импорта железнодорожной сети (GeoJSON)

Сеть описывается одним файлом GeoJSON `FeatureCollection` в системе WGS-84: координаты задаются как `[долгота, широта]`. Демонстрационный пример — `backend/app/configs/network_demo.geojson`.

Демо-сеть условная: координаты и состав перегонов не являются данными реальной инфраструктуры. Поэтому в интерфейсе она помечена «Демо-данные · условная сеть». Реальные названия станций не делают модель точной.

## Свойства коллекции

| Свойство | Значение |
|---|---|
| `properties.source` | `demo` или источник данных (например, `asu-2026-09`). Показывается в карточках. |
| `properties.note` | Пояснение, отображается во всплывающей подсказке пометки «Демо-данные». |

## Станция — `Point`, `properties.kind = "station"`

| Поле | Обяз. | Описание |
|---|---|---|
| `id` | да | Идентификатор. `@main` — основная станция: её координаты и ось берутся из `station.geo` конфигурации станции. |
| `detail` | нет | `detailed` — только для основной станции, остальные `simplified`. |
| `axis_deg` | нет | Азимут оси станции «запад → восток» в градусах от направления на восток, против часовой стрелки. |
| `half_length_m` | нет | Половина расстояния между горловинами, м. Для основной станции вычисляется из схемы. |

Для соседней станции параметры упрощённой модели (`receiving_tracks`, `max_train_length_m`, `processing_min`, `locomotives_available`, `accepts`) берутся из раздела `neighbors` конфигурации основной станции.

## Перегон — `LineString`, `properties.kind = "section"`

| Поле | Обяз. | Описание |
|---|---|---|
| `id` | да | Идентификатор перегона. Пути получают идентификаторы `id/1`, `id/2`. |
| `from`, `to` | да | Станции по `id`. |
| `from_throat`, `to_throat` | да | Горловина: `west` или `east`. |
| `tracks` | да | Число путей, 1…4. Второй путь сам не добавляется. Для двухпутного перегона путь 1 — направление `from → to`, путь 2 — обратное. |
| `length_m` | нет | Физическая длина, м. Если не задана, вычисляется геодезически по координатам (`length_source = "geodesic"`). |
| `max_speed_kmh` | нет | Допустимая скорость. |
| `coordinates` | да | Промежуточные точки трассы, без самих станций. |

## Обработка при загрузке (`app/domain/network.py`)

1. **Проверка формата** (`validate_geojson`): типы геометрий, обязательные поля, диапазоны WGS-84, ссылки на станции, стороны горловин, число путей. Ошибки возвращаются списком на русском, а `GET /api/v1/network` отвечает 422.
2. **Проекция.** Координаты переводятся в локальную метрическую систему ENU относительно центроида станций: равнопромежуточная проекция на сфере R = 6 371 008,8 м. Ось x направлена на восток, y — на север. На расстояниях до 300 км ошибка меньше 1 % (тест `test_projection_matches_geodesic_distance`). Градусы никогда не используются как метры.
3. **Горловины** — точки на оси станции на расстоянии `half_length_m` от центра.
4. **Геометрия перегона.** Перегон начинается в горловине, выходит из неё по касательной к оси станции на 1,5 км и проходит через промежуточные точки. Линия сглаживается центростремительным сплайном Catmull-Rom. Концы перегона совпадают с горловинами (тест `test_sections_start_and_end_at_throats`).
5. **Пути перегона** — параллельные смещения осевой линии:
   - физическое междупутье — 4,1 м;
   - на карте сети смещение увеличено для наглядности и плавно сходит к нулю у горловин.

## Подключение реальных данных

1. Подготовьте файл в этом формате, укажите `properties.source` и, если известна, физическую длину `length_m`.
2. Положите файл в `backend/app/configs/` и укажите его имя в `load_geojson(name)`. По умолчанию используется `network_demo`.
3. Проверьте `GET /api/v1/network`: ошибки формата возвращаются с кодом 422.
